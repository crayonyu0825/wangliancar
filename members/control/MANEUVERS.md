# 通用控制动作与上游交接

更新：感知/集成第一阶段复用原停稳计时，新增停车义务身份和独立执行观察，已接入
信号停点/停留的上一帧反馈。[当前接口与限制](../../perception/MANEUVER_ENVIRONMENT.md)。
已有独立[泊车/驶出候选生成](../planning/PARKING_CANDIDATES.md)，固定入口派发和灯光实际生效证明仍需补齐。

本次实现控制执行能力；所有动作由同一轨迹协议驱动。比赛规则中 07/08 要求倒车入位、停稳至少 10 秒再驶出；14/15/25 涉及稳定/弯道跟车及停止再起步；10 涉及停止线停车和绿灯启动；变道、绕障相关题目要求提前开转向灯。控制负责运动和执行器，上游负责行为、停车边界、路线、车身包络和碰撞检查。没有按题号新增控制分支。

## 轨迹契约

旧轨迹保持默认前进，公共固定函数签名不变。速度单位 m/s、坐标 m、航向 rad；点序始终是实际行驶顺序。`ego.heading` 是车辆车体航向，不因倒车加 π；控制做几何投影时自行换算行驶方向。轨迹点 `heading` 是期望车体航向；横向跟踪主要使用路径切向，精确停车另核对停车边界对应点的车体航向，按最短角度插值。停车边界可以在路径末点之前，不能一律使用最后一个点的 heading。

| 新增字段 | 默认 | 用途 |
| --- | --- | --- |
| `motion_direction` | `1` | 整个段前进 `1` 或倒车 `-1`；只接受整数，速度仍非负 |
| `precision_stop` | `False` | 有明确停车边界时使用低速末端接近与较小终点余量 |
| `hold_duration_s` | `0.0` | 到点后最短连续停稳时间；不表示起点立即等待 |
| `parking_brake_at_stop` | `False` | 已确认静止的保持阶段使用手刹；不在行驶中拉手刹 |
| `left_signal/right_signal/hazard_signal` | `False` | 上游显式灯光意图；危险报警灯在 SDK 发送时优先 |

`precision_stop`、非零停留或停车手刹必须伴随 `stop_required=True`。`stop_distance` 从本帧 GPS 后轴沿实际行驶方向到停车参考点计算，倒车也为非负距离。段内不能切方向；到换向处先结束当前段，再提交新段。所有输出仍须绑定本帧和原截止时间，不以新字段绕过 GPS、来源和安全监护。

泊车接近应有正的全局速度上限和末端降至零的点速度；示例字段如下，`points` 必须由真实规划给出：

```python
trajectory.motion_direction = -1
trajectory.target_speed = 1.0
trajectory.stop_required = True
trajectory.stop_distance = remaining_travel_distance
trajectory.precision_stop = True
trajectory.hold_duration_s = 10.0
trajectory.parking_brake_at_stop = True
```

既有 `target_speed=0` 停车命令禁止油门，适合减速停止；不能要求它在停车过早后再补油爬行。精确接近用正速度上限，距离/速度曲线负责收敛。停车边界已由上游扣除车体和安全余量，不能把控制的终点余量作为整个车辆的防碰撞模型。

## 算法与状态

1. **双向 Pure Pursuit**：倒车按 `ego.heading+π` 与路径切向匹配，沿点序选车后预瞄点。车体坐标曲率仍为 `2*y/(x*x+y*y)`，前轮角为 `atan(L*curvature)`；不额外翻转转向符号。短时位置预测用有符号速度 `motion_direction*ego.speed` 与实测横摆率。倒车预瞄限制在 0.8～3 m，速度最高 1.5 m/s。
2. **方向互锁**：`GEAR_STOP` 在 N 挡切油制动，连续低于 0.05 m/s 达 0.3 s；随后 `GEAR_ENGAGE` 请求 D/R，保持刹车 0.3 s，再进入跟踪。运动或意图反复变化会重新等待。GPS 原始 gear 不参与命令枚举推断；等待期间没有油门，也不表示已收到变速箱确认。
3. **动态速度执行**：局部点速度、全局目标、曲率限速、未来减速点、可信停距和路径覆盖共同取上限。PI、速度平方斜率前馈、积分抗饱和及踏板变化率跟踪这个需求。跟车误差与期望时距由决策处理；控制不重新选择前车。低速正需求使用 0.05 m/s 的保持释放门槛，仍确认两帧；按可执行的局部参考速度判断爬行，不把全局上限当作局部需求。PI 死区为 `min(0.08, 0.1*v_ref)`，避免固定死区吞掉 0.07 m/s 等爬行需求；零速和内部零速点不因此获得起步许可。
4. **精确停车**：终点余量从通用 0.5 m 降为 0.05 m，接近上限再取 `1.0*剩余距离`；静止阈值 0.05 m/s，到点位置/横向误差 0.15 m、航向误差 0.15 rad。较小末端超出容差内仍可制动，超过容差拒绝跟踪。这些是模型试验初值，平台仍需标定。
5. **停留与释放**：到点、对齐且实际静止后记录 `DWELL`；保留已接受的最短停留，即使上游提前请求驶出也继续制动。失效输入或实际运动/漂移重新计连续时间。完成并离开该停点后可接受新停留。可信案例/任务切换或显式会话 reset 会清状态；无效输入携带的新任务标识不能取消既有停留。同一上下文的可信帧号回退当帧拒绝并重新布防，未完成的停留保留并重新计时，后续新帧无需追赶原来的高帧号。停留结束后仍按明确的新轨迹意图释放和换挡，控制不自动选择驶出路线。
6. **优先级**：无效来源/数值拒绝正常控制，由运行层故障制动；有效急停当帧切油并请求 N 挡紧急制动，覆盖换挡/停留。灯光透传，手刹只在静止保持阶段使用。所有输出经过有限数、互斥、挡位和来源校验。

路径几何和方向不变时，投影使用上一进度以及 `max(v_now,v_previous)*dt + 0.75 m` 的前进范围，后退容差为 0.75 m；这可在已建立进度的自交路径上保留正确路段，防止跳到远处的后续段。仅更新速度不清进度，路径裁剪、改形或换向后重新锚定。没有可靠历史的自交歧义仍拒绝；失效、急停、换挡和重合点停车清几何记忆。这些边界是试验参数，并不保证任意重规划的路线匹配。

保留的完整轨迹和每帧裁剪的轨迹都可从实际零速起步。起步预瞄只作用于原路径
的初始非递减速度段，随车辆进度继续，仍受预瞄距离/加速度、全局速度、曲率、
末端及停止距离限制。第一次减速或中途零速终止这个前缀，后方再次升速不能
被用来跨过停车约束。这修复了原先预瞄只在 `s<=1e-6 m` 生效时，完整泊车
轨迹在微小位移后重新进入保持的问题；没有抬高规划的实际零速起点。

纵向积分范围为 ±10 m，在默认 `Ki=0.25 1/s` 下可提供 ±2.5 m/s 的稳态需求；试运行油门映射 0.1/(m/s) 因而可以利用 0.25 油门上限。旧的 ±3 m 在有持续坡度负载时可能先卡住积分，虽然踏板尚有余量。油门/刹车幅值、变化率、互锁与条件积分仍限制实际输出，超过参考速度时清掉不合适的正积分；未增加固定的坡道油门或猜测平台坡度。

诊断新增 `motion_direction`、`signed_body_speed_mps`、`hold_remaining_s`、`stop_pose_arrived`、`projection_continuity_used`、`stop_heading_error_rad`，状态新增 `GEAR_STOP`、`GEAR_ENGAGE`、`DWELL`。现有 JSON 发布自动保留字段，SDK 仍使用百分比模式和 `N=0/D=1/R=2/P=3` 命令；最短停留使用 N 挡和可选手刹，不在移动轨迹上请求 P 挡。

## 验证和未完成的整车交接

`tests/test_control_maneuvers.py` 使用带执行器滞后的双向自行车模型，覆盖左右偏差倒车、双向弯道、移动中换向、精确倒车停车/10 秒保持/前进驶出、直线与弯道跟车启停、输入失效重计时、方向抖动、到点姿态和倒车急停。SDK 边界测试核对帧、挡位、手刹、灯光和序列化；模型和 stand-in API 均不代表 SimOne 现场结果。

`tests/test_control_continuity.py` 补充前进/倒车自交路径、可达进度、改形重锚、帧回退恢复、无效上下文保护、精确停点航向及前进低速再起步回归。运行：`python -B -m unittest tests.test_control_maneuvers tests.test_control_continuity -v`，全量仍按根规则使用 SimOne Python 3.6。

`tests/test_planning_parking_generator.py` 进一步把实际生成的平行/垂直倒入及
前进驶出点列（保留零速起点和速度/时间）交给 `ControlEngine` 与滞后模型，
验证实际到点、10 秒连续停留和换向；`tests/test_control_planning_sampling.py`
另检查微小进度后起步、不同点密度和途中减速/零速保护。未接 SDK、未证明
真实跟踪误差/响应或执行碰撞安全，完整生产行为仍需上游接线和平台验收。

`tests/test_control_grade.py` 使用独立的带符号纵向力模型，覆盖 20 km/h 参考在平路、上坡、下坡和回到平路的跟踪，下坡停车保持及再起步，以及卸载后过速切油、积分恢复。±0.6 m/s² 重力负载和踏板增益均为模型参数，不能声称平台任意坡度都可起步或保持。`tests/test_control_parking_shapes.py` 覆盖合成的 90° 垂直倒入及双反向曲率的平行倒入，末端对齐、至少 10 秒停留和前进驶出；这里只测试轨迹执行，不生成生产车位路线或证明无碰撞。

`tests/test_control_real_pipeline.py` 使用真实 `decide → plan → compute_control` 固定入口及连续新鲜的合成观测；没有 mock 算法输出。它验证远处静止车起步后停车、直线/弯道前车停车再起步、红灯停车与绿灯后五秒内再起步。车身尺寸、踏板响应和曲线目标的 0.05 m/s 运动容差为显式测试参数，不声称已接收真实 Sensor API。默认生产运动容差仍为 0，现场噪声/曲线折线误差需按日志核对。

生产规划默认字段仍为前进，尚未生成倒车/泊车和换道路线。已合并主分支的保守障碍停车规划，非空目标在可信来源和明确车身尺寸下可消费；不再一律拒绝。`StartCaptain.bat` 按用户此前提供的 SimOne-Car 预设传入后轴至前缘 3.9187 m、车身半宽 0.9 m，保留调用环境覆盖并记录实际参数。运行层仍要求车道与场景必需来源，停车场如果无可用车道还需要集成层明确经过验证的自由空间参考与质量门槛，不能删除原安全 gate。当前独立安全 TTC 主要针对前方同车道目标，不能当作倒车扫掠碰撞检查。实现泊车全链需上游碰撞验证和后方可靠观测，再进行平台低速验收。启动/结束脚本仍为 `scripts/StartCaptain.bat`、`scripts/KillCaptain.bat`，无需将控制算法文件直接填入平台。
