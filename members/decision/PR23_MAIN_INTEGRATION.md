## 数据和接线

新增公共 `core.task_route.TaskRouteFacts / TaskDecisionInputs` 复用 main 的 `Evidence / GoalPose`。旧 `members.decision.behaviors.task_progress.TaskRouteFacts` 导入保持兼容。没有新增另一份行为通道。

每个策略会话使用独立的意图 ID 命名空间，意图内部仍保持稳定 ID 和递增修订。规则停车、任务跟随等策略切换或替换时，不会复用另一策略的旧反馈或规划修订缓存。运行诊断版本为 `decision-main-pr23-integration-v1`。

`CaptainRuntime` 支持可选 `task_inputs_provider`；标准启动可从既有确认模型文件的 `task_route` 配置安装。来源必须符合当前任务、地图、帧、时钟及原期限；缺失输入保护。提供者返回当前事实，不返回诊断快照或先验成功状态。

任务请求使用同一字典合同：`CONTINUOUS_TASK / FOLLOW_ROUTE`。明确规则停留使用 `RULE_STOP / STOP_AND_DWELL`；既有 `SIGNAL_STOP` 仍保留原严格 >5 秒门槛。受阻使用原 `BLOCKED_ROAD / STOP_AND_WARN`。这三类前进停止请求复用原 StopBehaviorPlanner 和普通速度/停止规划，并仍经过已配置的 P02 检查与执行监护。

控制只补充这些阶段的实际到位观察；不生成上游目标，不把规划确认或发送成功当作完成。任务完成还要求当前 GPS 与匹配实际反馈均整车在目的地区域、实际停稳且所需义务完成。

自动泊车使用 `ParkingMissionSelector`，输出原 `ParkingMission`。最终后轴目标由真实车位边界和确认车型计算；接近点来自本帧所选道路和车辆制动/误差模型。选位后冻结，后续占用/地图/任务变化由原停车事实和 P04 拒绝，不逐帧换目标。通道/入口、允许车位、朝向及驶出目标仍须由明确任务授权，不能由空目标列表推定。

## 跨模块修改的必要性

- `behavior_inputs.py`、`runtime.py`：安装同一当前任务输入和能力；保持原传输和独立监护。
- `core/maneuver_facts.py`：公开查询记忆目标的完整 Sensor 可见包络，复用原带预算的可见区域查询。
- `core/task_route.py`：将已有 D09 事实提升到 SDK 独立公共层，保留旧导入。
- `members/planning/behavior_contract.py`、`stop_behavior.py`：消费主线合同中的新停止目的；原同帧、修订、期限、能力与反馈检查不放宽。
- `members/planning/parking_behavior.py`：同阶段的新修订重新求解实际剩余路径，原终点/车位/入位/换向义务不变。
- `members/control_stub.py`、`core/validation.py`：补受阻/任务阶段的实际到位反馈和同帧规划确认校验；无确认、错误身份和非前进停止形状仍拒绝。
