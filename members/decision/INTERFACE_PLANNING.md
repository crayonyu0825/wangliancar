# 决策 ↔ 规划 接口现状与交接

V1 决策曾在 PR #4 提交；当前通用决策框架沿用固定 `Perception → DecisionTarget → Trajectory` 协议。这里只记录现在的接口语义与仍需跨成员确认的项目，旧版“非空目标一律被规划拒绝”的结论已被 [带目标轨迹约束](../planning/OBSTACLE_GUARD.md) 部分取代。

## 当前可消费的目标

| 决策场景 | 公共输出 | 规划消费 |
| --- | --- | --- |
| 空路巡航 | `KEEP_LANE`、正目标速度、`stop_distance=-1` | 正常车道参考及点速度 |
| 已知静止障碍或红灯尚远 | `KEEP_LANE`、有界正速度、已扣余量的非负停车距离 | 速度轨迹不得超过停车边界；有传感器目标时还要通过车身尺寸/目标包络门控 |
| 同向移动前车 | `FOLLOW`、有界速度、当前自车车道 ID；可同时带其他停车边界 | 接受决策速度上限，同时独立检查目标扫掠包络；车身尺寸缺失、与路径冲突的横穿/迎面运动仍会拒绝 |
| 已到停点且静止 | `STOP/0/0` | 当前点保持 |
| 停车点未知且车辆在动、近风险或必需来源失效 | `EMERGENCY_BRAKE/0`，未知边界为 `-1` | 既有制动请求与运行监护出口；不把 `-1` 当测得的停点 |

`stop_distance` 始终从 GPS 后轴参考点沿已知路线到**停车点**，由决策扣除目标后缘/车头/业务余量。规划不会对同一个决策停点再次扣余量，独立目标几何优先使用决策的 `obstacle_clearances_m` 按目标 ID 的净距，其他目标使用 `obstacle_clearance_m`；旧生产者传 `-1` 才回退规划余量。决策 `precision_stop` 透传既有轨迹精确停车标志。字段与默认参数见 [链路修复](../../P0_HANDOFF_FIXES.md)。`target_speed` 是行为需求，实际点速度受规划加减速、曲率与目标约束。`target_lane_id` 在本轮保持自车当前车道；后继车道目标只影响内部关系，不能被当作变道指令。

2026-10-03 补齐路线段边界：感知在 `LaneContext.forward_lane_spans` 发布与 `forward_lane_ids` 对应的完整参考线起止点索引。决策校验范围后按已核实的目标车道投影，支持多段后继上的前车。旧快照默认空列表；边界未知或不一致时仍保留更远后继的未知保护。字段与验证边界见[连续路线说明](../../perception/ROUTE_CONTINUATION.md)。

## 仍需队长协调

1. **车身与制动参数**：确认当前 SimOne-Car 后轴到车头、最大半宽、可用减速度和延迟。决策/规划目前共享 `NEVC_VEHICLE_FRONT_OFFSET_M` 语义；规划还需 `NEVC_VEHICLE_HALF_WIDTH_M`。缺实测值时不宣称带目标轨迹可在平台运行。
2. **预测与让行**：现有四个公共模式不能表达完整横穿时序、变道、绕障、泊车或倒车。当前不把内部 `YIELD` 状态当作新整车能力；若需明确时间窗、目标 ID 和预测轨迹，由队长统一公共字段和来源帧语义。
3. **失败反馈**：`decide(perception)` 收不到上帧规划/控制失败结果。持续不可行只能从 `latest_pipeline.json` 诊断；若要反馈闭环，队长定义公共协议，不在决策读取诊断文件构成隐式环。
4. **静止判据与刹车**：决策 `standstill_speed`、规划零速阈值及控制 HOLD 阈值不同。应按真实车辆响应统一验收，不能仅凭合成测试宣称停车准确。

## 验证边界

离线测试已调用真实 `plan(perception, decision)`，检查静态接近、已知/未知停点、移动前车与紧急请求的输出形状。带目标的实际平台能力仍取决于可信 Sensor API 来源、车身尺寸及 SimOne 场景反馈。默认 `send_control=false` 未改变。
