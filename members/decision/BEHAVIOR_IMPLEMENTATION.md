## M0：身份、反馈、能力与失败出口

[合同草案](BEHAVIOR_HANDOFF.md)对齐既有规划 R05～R09。`TaskContext`、`BehaviorFrame`、`BehaviorGoal`、`BehaviorRequest`、`ExecutionFeedback` 和 `Capabilities` 都是独立类型。默认观测/反馈不可用、下游能力为空；没有获得能力时只有 `dispatch_allowed=False` 的提案。公共 `Perception`、`DecisionTarget` 未私增字段。

`BehaviorSession` 维护稳定意图、阶段与语义修订；帧间速度/剩余距离更新不重新创建任务。上下文、意图、阶段、修订、候选身份、来源帧、生产帧、明确的本机时间与年龄都必须对应。上一帧的新鲜反馈可消费，重复、乱序、未来和错误来源反馈不能推进。规划接受不是实际完成；控制发送也不是停稳证明。无效新任务信息不能抹掉未完成义务。

暂停、急停、失效及长观测间隔保留阶段并撤下派发；恢复递增修订重新核对。路径拒绝最多按明确 retryable 重试，接受和实际无进展都有超时；规划重复确认不能掩盖执行停滞。证据恢复也只允许同一意图累计有限重验。非重试拒绝、完成和取消不能被目标变化、失效帧或能力切换抹掉；只有新的受信任任务/动作或明确证据重验才能重启。完成、取消和阻塞明确清方向灯；双闪仅在受阻政策仍适用时保留。

## M1：D01、D02

**D01** 的 `BlockedRoadPolicy` 用已验证路线阻断和可通行方案状态判断双闪请求；正常红灯和普通跟车停止被排除。`SignalDwellPolicy` 请求超过 5 秒（实验政策默认 5.1 s）的最短停留，只有对应控制/运行反馈同时证明到点、实际静止、持续时间足够和完成，才解除义务。到点前不计时，提前绿灯不缩短义务，漂移/重复/暂停不完成它；同一停点完成后不重新计时。策略不维护另一套控制倒计时，跨阶段停留身份用拟议 `stop_obligation_id` 保留。场景 20/11 只选择任务书要求的停留/灯光政策，场景编号不决定障碍与碰撞。

生产 `decide()` 可从现有真实事实产生 D01 **未派发**提案；`decision_behavior_info()` 仅是独立诊断读取口，不是反馈通道。缺少 R05/R07 时不能宣称生产 20 题的停留或双闪已透传，也不能以诊断字符串绕过接口。绿灯上的现有正常输出与未接入的停留义务必须分别审查。

**D02** 的 `TargetHistory` 已接到真实约束收集：按稳定 ID 保存本机到达秒数、来源、路线位置/横向运动及质量，重复 GPS 不追加；来源切换、上下文变化、帧/时钟回退、长间隔或不可能位置跳变清掉不可信身份。安全前车暂失时在短窗口保留保守速度上界，与第二前车共同取最小值，不创建伪 Sensor 目标、不锁存停车；真实侵入和其他紧急约束优先。跟随过的车短时切出再停回路线保留跟车净距。危险消失继续使用 v10 的独立危险解除门控；全走廊/遮挡清空证明仍缺 R06/R09 输入，不能把 usable 空帧提升为完整覆盖。

## M2/M3：D03、D04 的独立策略

**D03** `LaneChangePolicy` 复用换道、绕障、超越、汇入流程。候选须有同向几何、两侧边界、合法虚线可跨范围和侧后新鲜覆盖。按车身、前后车速度及动作时间窗检查间隙；未知加速度用显式保守范围，而非假装准确预测。初选优先当前安全机会，选定后不逐帧摇摆。`PREPARE → WAIT_GAP → REQUEST_PATH → EXECUTE → SETTLE` 由真实灯光生效证据、关联规划接受及实际车道/整车姿态推进；执行中受阻转恢复路径需求，不立即切回中心线。实际左右边界优先于宽度摘要，整车角点及车身边缘须在已核实走廊内，不能以车道 ID 或后轴进入代替稳定。重验次数在同一意图跨阶段累计有限。

**D04** `ParkingPolicy` 验证车位占用、自由区域、前后观测及整车尺寸后选择可容纳车身的位姿。后轴目标由车身前后长度换算，不能拿车位中心替代。接近和预入位姿须由已核对的候选输入提供，未提供则拒绝。实际到点和停稳才进入下一方向段；入位位置、车体角度、整车位于车位内都满足后才进入停留。至少 10 秒由控制反馈证明，随后才请求已验证驶出目标。非预期倒退、后方新障碍、错误到位或未知覆盖保留保护。垂直/平行场景通过真实几何目标区别，不按题号制造路径。

## M4：D05～D07 的独立策略

`OccupancyTracker` 合并全组对象的保守恒速扫掠窗口；地图区域、动态覆盖、信号和规则各有证据。ID 切换或短时消失不意味着区域清空，折返/进入预测参与；已核实覆盖连续清空后可解除。支持的区域为凸多边形，非凸/未知几何需上游提供可核对分解，不能伪造区域。侧边无关目标不占用横道。

`IntersectionPolicy` 将上述占用和规划的通行窗口、真实入口停车边界、信号、明确路权及出口空间共同仲裁。绿灯不覆盖目标冲突；出口不能容纳车身及净距时在入口前等候。已经在路口内时使用验证后的驶离目标或最小风险路径需求，不把入口停点重新套上、也不猜测倒车。清空确认没有人为长等待，合成测试验证可在 5 秒内发布恢复条件；现场起步时限仍需真实全链验证。`INTERSECTION/CROSSWALK/JUNCTION_ENTRY` 复用同一几何/占用逻辑。

## M5：D08、D09 的独立策略

**D08** `EmergencyPolicy` 在等待任何候选期间始终保留即时制动需求。只有关联意图/阶段/修订及特定候选 ID 的新鲜规划反馈，明确可行且满足侧向覆盖与规则条件时才选候选；按风险、规则代价和稳定 ID 排序。新危险令旧候选失效并重新选择；全部未知/不可行保留最小风险制动，不能宣称避免碰撞。危险清空、实际执行结果和原任务路线都已确认才回归任务。

**D09** `TaskProgressPolicy` 消费明确的段身份、已选分支和可达累计进度，不用全局最近点跳到返程段。局部窗口、查询失败或分叉歧义不等于任务完成。临时动作期间保留原规定路线；目的地区域、精确目标姿态、实际停稳与正确反馈共同满足才完成。无进展、帧回退、任务切换和拒绝都有出口。

## 配置、测试和后续兼容

生产新增参数仅在 `DecisionSettings`，仍支持 `NEVC_DECISION_` 覆盖和显式优先。目标历史默认最多 128 个 ID、每个 8 条、保留 1 s、交接 0.4 s、长间隔门槛 0.5 s，跳变余量 3 m、制动不确定性 2 m/s²。独立策略的动作窗、间隙、姿态与占用参数可通过各策略构造参数替换；它们均为合成验证初值，不是车辆或赛事能力。

## 审查修复与 Windows 目标环境验证

2026-10-08，修复审查复现的三个问题：

- 紧急危险身份变化时，即使仍在 `SELECT` 阶段，也强制递增同一意图的修订并更新来源帧/发起时间，拒绝旧危险的候选反馈；累计重试预算保留。
