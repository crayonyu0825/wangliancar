# P03：固定入口与实际执行反馈

固定 [plan](../planning_stub.py) 已可将正式 D03 请求交给
[LaneChangeBehaviorPlanner](lane_change_behavior.py)，复用已有五次生成器、
正式 ManeuverFacts/P02 校验、普通前进规划器和控制/运行反馈。默认不提供
车型/运动输入适配器，也不增加运行能力；生产协调器自动选择 D03 意图、
真实灯光确认及现场验收仍待完成。

## 输入来源与配置

`configure_planning(config, lane_change_inputs_provider=adapter)` 保留原返回值。
原运行调用只传 `config`，因此默认仍无 P03 物理模型输入。队长可提供只读
`adapter(perception, task_context)`，返回 `LaneChangePlanningInputs`。适配器
须自行核对物理来源；本接口不把标签、配置开关或能力声明当作标定证据。

快照逐帧包含任务/会话、当前帧、原产生时刻、独立期限、同进程时钟、模型
修订 ID、当前有符号曲率（左正、1/m），以及已有 `VehicleGeometry`、
`MotionLimits`、`LaneChangeSearch`、`ValidationBudget` 和按实际对象 ID
完整给出的 `PredictionEnvelope`。当前曲率的参考点、单位、误差、停稳时
的观察方法及预测/响应误差界须由来源适配器明确建立。不能把原始 GPS
`steering`、零车速、概率或空目标包直接换成零曲率、零误差或覆盖证明。

快照必须与当前任务/帧/时钟匹配，期限不超出当前感知；调用方参数会复制。
模型 ID 仅表示调用方的模型修订，同一活动意图还冻结车型/运动参数、地图
摘要、原源道/目标道、后轴终点及灯光侧。预算与原请求、能力、模型及正式
环境期限共同收紧，搜索和连续校验共用工作上限；晚返回也不能发布过期路径。
显式复用 `ManeuverGeometryCache` 时本消费者至少需 6 项，分别容纳双道候选
的 4 类静态几何和确认期间当前道/可见区域的 2 类几何。缓存仍不存安全结论。

## 阶段和路径

原 P01 边界复用任务、身份、修订、创建/生产帧和时钟核验，显式增加运行
P03 分支。仅接受 `LANE_CHANGE/AVOID/OVERTAKE/MERGE` 的
`REQUEST_PATH/EXECUTE/SETTLE`，前进、不同原源道/目标道、明确固定后轴
终点、正速度授权及单侧方向灯；停车/车位/停留扩展不混入此消费者。
缺少 `PATH/LANE_CHANGE/LIGHTS/FEEDBACK` 任一能力时拒绝。

`REQUEST_PATH` 先校验换道候选，随后以现有普通规划器产生当前实际车道的
临时前进轨迹；速度上限取原决策与请求的较低值，停止边界收紧到当前正式
局部道路的车身容纳范围。该轨迹另经同一车型/运动/对象/视野模型的 P02
连续校验，剩余预算与候选共用。通过后发送 `PLANNED`，轨迹仍指向当前道，
起始位置/朝向/速度必须保留实际观察，当前曲率至首段的转向速率也单独核对。
没有换道执行身份，也不发布换道候选点列；普通控制与独立监护继续工作。
无法在当前道连续容纳的跨线恢复会明确拒绝，不能借确认阶段回弹到另一道。

决策消费确认后明确进入 `EXECUTE`，此时重新读取实际位姿/速度/曲率、对象、
视野及原期限，重新生成固定终点路径；仍跨线时重查原方向许可，`SETTLE`
同样重新核验。没有成功的同意图 `REQUEST_PATH`，冷启动执行拒绝；相同修订不能换
阶段/创建身份，递增修订也不能悄悄更换原绑定。P03 不回落成普通循迹来
声称换道已接受。STOP、急停、已知停止距离或任何必停信号均优先撤下 P03。

### 整车进入目标道后的剩余路径

只有已成功确认的原意图处于 `EXECUTE/SETTLE`，才允许生成器的显式
`allow_target_lane_continuation` 分支；普通组件调用默认仍要求原跨线依据。
SDK 当前道为原目标 B 时，先以同一车型和 P02 对实际位姿作整车几何检查。
整车在本帧 B 内后，剩余曲线从实际速度/曲率出发到原固定终点，全程只使用
当前 B 的正式道路范围，另查全部原对象预测和完整视野。此时不再依赖 A 的
邻道几何或跨线许可，也不能借 B→A 的许可再次离开 B。

车身尚跨 A/B 时只有原跨线分支可继续，已用的车身检查工作量从共享预算
扣除，当前道来源期限也继续收紧。未知/预算未决不会当作车身已入道，入道后
曲线出 B、目标侵入或视野不足不能回退到双道并集绕过检查。初始几何探针
不是零速执行观察；实际曲线仍保持实际起始速度、朝向及曲率限制。

决策区分车身容纳与朝向稳定：整车已在 B 内且朝向仍同向时可继续受检回正，
完成仍要求原朝向容差、连续 GPS 与匹配实际反馈；继续移动不证明已完成。
新增[剩余路径回归](../../tests/test_planning_target_lane_continuation.py)包含来源消失、
SDK 编号先切而车尾未入、回正阶段、两侧方向、动态侵入、期限/预算、冷启动
和撤去原邻道后的真实固定入口/运行反馈/迟滞车辆连续模型。

## 控制与运行交接

移动轨迹使用已有 `behavior_identity`，无需虚构停留义务；公共边界只在
执行/稳定阶段、有同帧同身份的有效规划确认时接受这种扩展。原信号停留
身份仍要求真实停留义务和正持续时间。三个固定函数签名和 JSON 字段不变。
现有控制入口已会为身份匹配的有效轨迹提供实际执行观察；移动路径没有
停稳义务时不报告到点、停留完成或灯光确认。

原运行反馈的停车距离进展不适用于换道。现在对活动阶段复用实际 GPS 到
固定后轴终点的距离减少量，按同意图/修订保存有界进展；重规划不会每帧清
零。它只用于“是否仍有实际进展”，不能代替整车/朝向稳定、到点或完成。
同一修订目标变化撤回为失败，发送/安全中断仍报告失败。决策新阶段通过
原 Session 在本帧重新核对新能力，旧反馈不重放，时钟与稳定帧不重复累计。
距离减少是当前有界进展模型；长弯或绕行可能不单调，仍须结合正式任务路线
核验相应的进展与超时策略，不能据此声称任意弯道均已验收。
