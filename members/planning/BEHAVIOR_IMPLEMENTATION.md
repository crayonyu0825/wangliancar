## L0：可以独立推进的基础

### P01 请求边界

[behavior_contract.py](behavior_contract.py) 的 `assess_behavior_request` 独立核对请求形状、版本、任务/会话、意图/阶段/修订、帧、同进程时钟、目标和能力。输入字典与 [决策 PR #20 的 M0 草案](https://github.com/lsl1111/wangliancar/blob/fc4251525228cded4bf0938d0829d17c01dd5100/members/decision/BEHAVIOR_HANDOFF.md) 对齐，不导入其私有实现；目标字段在请求顶层展开，不能另嵌套成 `goal`。

修订的 `source_frame_id/issued_at_s` 表示创建该修订的历史时刻；当前请求的 `produced_frame_id/produced_at_s` 表示本次生产。前者可以早于当前帧，不能每帧重建意图；当前轨迹仍需绑定实际本帧输入。活动身份由未来获批准的运行通道提供，校验器不自行创建决策状态机。

默认支持动作集合为空。显式开启已有前向 KEEP_LANE/FOLLOW/STOP 也只用于组件试验；灯光、停留、停车手刹、非空停留义务身份、目标位姿、换道或反向请求不能被忽略后降成普通前进。合同检查成功只表示 `READY_FOR_COMPONENT`，不等于已有可行轨迹、`PLANNED` 反馈或实际执行完成。生产 `plan` 尚未调用该组件。调用者须传实际检查时刻，允许同帧请求稍早生产，但检查期间已过期的输入不能通过；组件不能独立证明调用者的时钟与来源可信。

这些模式请求是手工构造的试验子集，尚不能消费 PR #20 实际 D01 的 `SIGNAL_STOP/BLOCKED_ROAD` 或新换道等动作。能力词汇沿用其 `PATH/PATH_STOP`，本地动作启用单独检查。[合成请求样例](examples/behavior_request.synthetic.json) 默认不可派发、能力不可用，展示明确拒绝而非虚构接线成功。

可独立读取该样例检查边界，外层说明字段不传入校验器：

```python
import json
from members.planning.behavior_contract import assess_behavior_request

with open("members/planning/examples/behavior_request.synthetic.json", encoding="utf-8") as stream:
    data = json.load(stream)
result = assess_behavior_request(data["request"], **data["call_arguments"])
assert result["reason_code"] == "REQUEST_NOT_DISPATCHABLE"
```

样例时间为合成数值。真实接入必须由公共通道提供当前可信输入、实际检查时刻及活动身份，不能复制这些时间或有效标记。

### P02 整车与名义运动校验

[candidate_validation.py](candidate_validation.py) 独立接受真实接口的 `TrajectoryPoint` 序列、显式方向、整车尺寸、运动限制、凸多边形或显式简单轮廓并集、目标预测和检查预算，输出结构化检查结果。详见 [候选校验的模型、接口与限制](CANDIDATE_VALIDATION.md)。

基础覆盖前后悬与四角、道路边界、点间扫掠、已知朝向矩形/未知朝向包围圆、明确恒速预测、点速度和时间及运动限制；不能证实时返回不确定，不因为采样点都避开障碍便宣布安全。结果针对给定插值和预测模型；实际控制按路径速度消费，不按相对时间追点，因此名义时空检查尚不是执行避碰保证。
