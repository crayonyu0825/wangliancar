# 候选轨迹校验基础（L0 / P02）

整车并集几何的实现现共享于 [core/corridor_region.py](../../core/corridor_region.py)，
原 [规划 import](corridor_region.py) 保持类型兼容；P02 连续扫掠继续使用同一
精确拓扑和距离引擎。决策的[正式泊车读取](../decision/PARKING_EXECUTION.md)
也复用其受预算限制的整车查询，不复制算法、不改变现有轨迹检查或路权边界。

当前增量基于包含 PR #20/#21 的 main `aa65aeb`，2026-10-09。实现位于 [candidate_validation.py](candidate_validation.py)，是规划内部可复用组件，不生成路径、不决定路权或车位、不发送控制。生产 `plan` 尚未接入；不能据此将全部 P02 或任何换道/泊车行为标为完成。

## 显式输入与输出

`validate_candidate(points, motion_direction, vehicle, limits, corridor, obstacles, budget)` 使用已有 `TrajectoryPoint`；位置是后轴中心，heading 是车体航向，速度非负，整段方向为整数 +1/-1。倒车时路径向后延伸，heading 不加 π。

| 参数类型 | 内容 / 单位 |
| --- | --- |
| `VehicleGeometry` | 后轴到车头/车尾、半宽、轴距，m；不借用目标物中心作为主车参考 |
| `MotionLimits` | 速度、纵向加减速度、横向加速度、最大前轮角及转角变化率；另显式给方向角/距离误差容限 |
| `corridor` | 原列表输入仍要求凸多边形；显式 `CorridorRegion([ring, ...])` 接受简单凹多边形的并集，保留缝隙、孔洞和不相连区域；不按邻道 ID 或默认宽度补造自由空间 |
| `ObstaclePrediction` | 目标中心、长宽、朝向、世界速度 vx/vy、相对预测时限，以及位置/速度不确定范围；None 朝向用外接圆，未知速度不补 0 |
| `ValidationBudget` | 有限检查数、细分深度、最小时间区间和本进程单调时钟截止；是调用者给的检查预算，不是已标定循环周期 |

空障碍列表只表示调用者为该独立检查明确提供了空列表；校验器不证明传感器视野或漏检范围。真实接入仍需公共来源、覆盖和原截止门槛，不能以几何检查重新使过期输入有效。

结果为内部字典：`status` 区分 `safe/unsafe/inconclusive/invalid`，并记录原因、约束、检查次数、耗时、模型假设及有证据的间隙下界。只有全范围检查证实后才给安全结果；预算不足、预测时限不足或无法证实不是安全。它不是 `Trajectory.valid`，也不是向决策发送的正式反馈。

以下小车尺寸与限制全部为手写数学例子，演示 2 m 直线路段的检查；既有真实车辆预设另在数据请求中保留，不用本例替代。

```python
import time
from core.interfaces import TrajectoryPoint
from members.planning.candidate_validation import (
    VehicleGeometry, MotionLimits, ValidationBudget, validate_candidate,
)

points = [TrajectoryPoint(0, 0, 1, 0, 0), TrajectoryPoint(2, 0, 1, 0, 2)]
result = validate_candidate(
    points, 1, VehicleGeometry(1.0, 0.5, 0.3, 0.8),
    MotionLimits(8, 3, 4, 4, 0.7, 4, 0.1, 0.01),
    [(-2, -2), (5, -2), (5, 2), (-2, 2)], [],
    ValidationBudget(1000, 16, 0.0001, time.monotonic() + 1.0),
)
assert result["status"] == "safe"
```

例中的 1 秒只作离线演示检查截止，不是在线规划预算。正式预算应由实际循环周期、输入截止和其他模块耗时确定。

## 方法与可证明范围

整车使用带前后悬的有向矩形，目标使用有向矩形；未知朝向目标使用覆盖所有朝向的外接圆。几何间距检查完整边和内部，接触视为冲突。道路检查整个矩形相对于区域的外露边界距离，因此可发现后轴仍在路内但前悬/车角越界，也能发现完全包含在车身内部的未知孔洞。

### 显式非凸与多区域输入

[corridor_region.py](corridor_region.py) 扩展原 P02 校验，没有另建生成器。输入最多 32 个轮廓、总计 20000 个 XY 顶点；兼容路径使用已有简单轮廓检查作保守预检，两条路径均用精确有理数检查自交、相邻折返、区域间交点及内部接缝。整数和浮点坐标按其实际表示值参与拓扑判断，不用 epsilon 吸合接缝；极小正间隙仍保留。可拒绝无法可靠处理的输入，不填成凸包。

例如将两个实际车道轮廓交给 `CorridorRegion([current_polygon, neighbor_polygon])`，只有被另一区域确实覆盖的边界片段才消除。部分接合、只接触一个点、重叠或包含均保留各自实际外露部分。这个构造只指定几何，并不证明跨线允许、完整检测或行驶方向；真实接入必须另查公共环境的来源、覆盖、任务、地图身份和原始期限。

整车与外露线段使用分离轴距离下界，再扣除端点转换及浮点运算余量，沿用原有连续区间细分。下界可以低于实际最短距离，不能高于它；清晰接触用精确判定确认，落在数值余量内但不能确认接触时返回 `REGION_NUMERIC_RESOLUTION`，不给安全结论。拓扑编译、轮廓预检、查询与细分均使用同一个次数/时钟预算。

原可变输入方式中，同一 `CorridorRegion` 可以复用已完整编译的静态拓扑，每次仍逐点核对当前轮廓，并重新校验运动、目标、预测时限和检查截止；中断的这类编译不复用。缓存不刷新来源，也不缓存轨迹安全结果。原凸多边形调用方式保持兼容。

原密集曲线离线性能检查使用合成 101/1001/3001 点车道、11 个轨迹点及宽松离线预算，3001 点首次约 1.27 秒、复用约 0.062 秒。后续分帧增量见下一节；这些测量均不构成循环时限保证，当前未据此启用新行为。

### 分帧静态准备与正式几何缓存

显式提供 `preparation_max_checks` 时，`CorridorRegion` 使用不可变的嵌套 tuple
轮廓，复用原精确拓扑算法分帧准备。有限顶点、精确面积/折返/交点、内部接缝、
边界片段和查询树都保留；排序、拓扑与索引的工作可在原子步骤之间中断。
这条路径以精确拓扑独立验证轮廓，不依赖不可续算的浮点预检；可变列表输入
仍使用原兼容路径。

各次 `validate_candidate` 仍受本次次数和单调时钟预算限制。预算耗尽时给出
`BUDGET_EXHAUSTED`，静态进度保留但半成品不可查询；全局准备工作总数另受
调用者明确的上限限制，达到后返回 `REGION_PREPARATION_LIMIT` 并保持未确认。
错误/上限不因下一帧重新获得预算而消失。更换不可变输入会撤销旧拓扑并重新
准备；完整准备完成后，每次候选仍重新检查运动、动态目标、预测时限和截止。

[正式场景适配器](maneuver_scene.py) 可由调用者传入
`ManeuverGeometryCache(max_entries, preparation_max_checks)`，按案例/任务/场景/
地图摘要、选定车道和完全相同的世界轮廓保留准备进度。缓存数量有界，任务或
地图改变时清空；几何变化不借用旧结果。每次场景读取仍先核对正式来源、当前
GPS、原动态期限、完整覆盖和高度，缓存只持有静态几何，不持有空闲或安全证明。
容量须明确为 2–16 项，至少保留道路和可见范围。缓存对象轮廓被替换时按当前
正式事实重建；道路和可见范围分别准备。候选完成后仍需核对当前正式事实，
派发期限不得越过原来源期限，在当前源截止前未完成候选检查时不能派发。

合成 3001 点车道、11 轨迹点的单次离线检查中，准备分为 109 次调用，累计约
1.70 秒；8 ms 名义截止下单次调用最长约 16 ms，复用后完整名义校验约
0.047–0.062 秒。Windows Python 3.6 时钟精度和原子操作不能提供硬实时保证；
在线仍需实际循环预算、窗口更新/预取调度和车辆闭环验证。该增量没有生成路径
或启用新行为。

### 整车跨线开口与原车道周界

[CrossingCorridor](crossing_corridor.py) 在原 P02 连续整车扫掠中保留原车道的
完整规范化 SDK 周界，只移除正式感知已绑定的共享边界许可片段。左/右侧均可
使用，非共享侧和两个端部保持禁止跨越；不能通过绕过有限许可窗口或车道末端
避开约束。多个许可范围按精确参数并集处理，正间隙不会被填平。

许可端点采用原始线段索引和有理数比例，分子/分母用规范十进制字符串保存，
JSON 回放不将它们压成浮点数。世界 XYZ 是该精确位置的浮点表示；显示弧长
用于窗口定位，不用于外推许可。原生端点直接保留，裁剪和加密也进入已有感知
分帧预算。输入仍是既有 `points3` 规范化后的 SDK 折线；源记录由队长生产者
提供，读取器不重查 SDK，也不构成连续实际涂线或真实道路误差界的证明。

完整周界的禁止部分与道路外露边一起进入原查询树，车角、前/后悬和位于车身
内部的短禁止段都参与检查，点间运动继续使用原位移/转角上界。精确端点转换
及浮点误差从下界扣除，未分辨清楚时保持未确认。原静态准备次数/截止与总工作
上限继续适用，半成品不发布。

[场景读取器](maneuver_scene.py) 对包含当前车道和一个邻道的输入提供独立
`legal_crossing_corridor`，道路 `corridor` 和可见 `coverage` 保持原用途。换道
生成器须同时检查合法跨线区域、完整可见范围、动态目标、运动与当前原期限，
不能只检查道路并集。缓存这三个对象时须至少 3 个条目；源车道的两条完整边界
必须仍与当前感知一致。这不替代普通后继前进、汇入口或泊车驶出所需的授权。

该组件只证明所提供的名义几何/插值模型内完整车身符合开口约束。实际地图
标线语义、传感器覆盖、车辆/跟踪误差、执行时钟及控制响应仍需各自核实；生产
换道生成器、请求调度和实际灯光反馈仍未启用。

速度/时间采用分段恒定切向加速度模型：段长与 `(v0 + v1) * dt / 2` 在显式容限内一致。段内按积分行程插值后轴位置，heading 按空间比例取最短角度；同时核对方向、曲率/转角、速度、纵横加速度及采样转角变化。该模型和容限是检查假设，不构成严格无侧滑动力学或轮胎/执行器模型。

容限内的距离残差会使空间映射比例变化，组件按映射后的实际名义速度/加速度复核限制，保留原点不变；不能用容限放过插值后的超速。三点几何曲率另行检查，防止错误的 heading 属性掩盖折线路径转向需求。转角变化率等仍为离散约束，段接头的连续动力学与实际跟踪另需验证。

几何检查使用连续的实际移动段，跨过任意数量的同位置零速停留点；以移动段的方向与长度核对转弯需求，并使用两侧实际名义速度核对横向加速度。转角变化率保留原轨迹到达转折位置的时刻。完整原轨迹仍用于速度/时间和连续碰撞检查，停留期间的动态占用不会被去重删除；非零速度或车体旋转仍不能作为静止段通过。

连续碰撞不只看端点。每个时间区间在中间时刻计算整车与目标/道路间距，再扣除区间内任何车体点可能移动的上界：后轴位移加上“最远车角半径 × 航向变化”。目标再计恒速位移与显式不确定范围。如果剩余间距仍为正，可证实整个区间；否则自适应二分。达到深度、检查数、时间截止或分辨率仍不能证实时返回不确定，不能漏掉细障碍后仍宣称通过。

这是给定插值、恒速固定朝向目标与不确定范围内的名义时空验证。控制当前按空间进度消费 `v(s)^2`，不保证车辆在轨迹相对时间精确到达。依靠时间错开的通过结果，在实际接线前仍需跟踪误差、响应延迟与时钟误差的界限；当前不保证实际动态避碰。

保留主分支 `reference_recovery` 的旧走廊/几何修复；此组件处理显式新候选和目标时间占用，不修改已有目标投影、运动分类或当前车道跟踪。生产参数来源未知时明确拒绝；示例/测试参数均为合成工程条件，不标为实测能力。
