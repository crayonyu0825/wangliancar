## 实际接线与跨成员影响

```text
原始 SDK / 明确任务和模型
  -> PerceptionBuilder / ManeuverEnvironment（保留源、地图、覆盖和原期限）
  -> 成对输入桥（决策和规划读同一帧、同一模型）
  -> decide -> plan -> compute_control
  -> 独立当前路径检查 + 上次成功发送轨迹的执行监护
  -> 原 SDK 发送函数 / 回执
  -> 实际进度、到位、停稳、驻留反馈 -> 下一周期 decide
```

- 公共协议：`Trajectory.candidate_id/planning_metrics` 和正式反馈补充候选提案、灯光命令证据、发送状态、未知挡位确认与真实制动停稳结果。旧通道快照缺少新可选字段仍可读取。
- 决策：承接换道/绕障/汇入任务、通行授权、分段停车及紧急候选采纳；高优先级停止义务继续有效。规划不能自行返回原车道或提前驶出车位。
- 静止绕障的车道衔接：只在已有正式采纳、原对象仍连续观测、任务/模型/来源一致、实际姿态进入指定目标道时解除该对象的旧危险确认等待；对象仍参与 P02/P05。仅修改车道标签、目标消失或位置跳变不能使用这一条件。等待轨迹的道路末端停车同时扣除原执行误差所需余量。
- 感知：从实际 SDK 所选地图边界补所选通行/接续道路；验证横道原记录、关联停线、出口及当帧 Sensor 覆盖；记录原始 GPS 转向和目标速度字段是否真实存在。兼容默认的零值不被当作运动观测。
- 控制：补中间停车段到位反馈、保护未结束驻留；立即制动保留已经建立且与实际运动一致的方向，以便随后同向转向加制动；换向仍需实际停车。没有用控制限幅掩盖上游不可执行路径。
- 运行与安全：标准入口安装配置供应器；每帧检查独立路径和旧发送轨迹；只有 `attempted=true && ok=true` 且无安全覆盖时登记原轨迹。暂停、失效及安全覆盖不推进完成或驻留。

### 紧急提前停车的语义

物理车辆可能在授权目标之前停下。原 `goal_pose`、候选编号保持不变，`goal_pose_arrived=false`，不将进度填写为 1。原移动轨迹不可行时保留拒绝原因，决策授权 `BRAKE_FALLBACK`，继续制动而不加速。实际零速后重新验证当前整车、全部目标、覆盖和旧执行记录；只有独立检查通过且实际成功发送保持制动，运行层才报告 `actual_brake_stop_confirmed`。危险连续新鲜解除并有合法任务道路后，决策以“真实制动停车后恢复任务”结束紧急事件；该结果不声称原避让终点已到达。

## 配置与现场启动

入口仍为仓库根目录 `main.py` 和既有 `scripts/StartCaptain.bat` / `KillCaptain.bat`。启动器支持本机环境变量 `NEVC_PYTHON_EXE` 指定已经确认的 SimOne Python；未指定时保留团队原默认位置。使用本次分支所在目录作为平台脚本目录；指向其他 main 工作树的启动脚本不会自动执行本分支。

标准 `CaptainRuntime` 经 `behavior_model_file` 安装配对来源和能力。使用方法、未确认模板、每项数据负责成员见 [行为输入配置](../../config/BEHAVIOR_INPUTS.md) 和 [JSON 模板](../../config/behavior_model.example.json)。默认文件为空，模板 `verified=false`，未知数值为 `null`；这些不是现场标定数据。合法且确认的输入能启用对应动作，不是让全部能力永久关闭。

需要队长/负责成员提供：实际车辆与 GPS 转向映射、适用的执行位置/朝向/提前滞后/速度误差、Sensor 完整视场与遮挡依据、目标预测误差、实际任务/所选地图/车位及路权窗口。模型配置不替代实时地图或 Sensor 观测，不延长原来源寿命。配置任务确认和现场控制授权是两件事。

`send_control=false`、`safety_brake_enabled=false` 均保持默认。真实开启仍执行团队联调流程；本次开发没有在 SimOne 中发送车辆命令。

动态速度组件另在目标解释器上每场景重复 10 次，以高精度 `perf_counter` 计时：简单清路/静态限速约亚毫秒；50ms 预算的横穿及横穿加第二静止目标场景均为 10/10 预算耗尽；250ms 预算下，单目标横穿 10/10 找到安全解，横穿加第二静止目标 10/10 为 `NO_CERTIFIED_DYNAMIC_PROFILE`，未耗尽预算但没有得到安全候选。两种复杂场景用时约 150ms 量级。预算耗尽或未获得完整证明不输出候选。Windows 该解释器 `monotonic` 分辨率约 15.625ms，求解额外保留预算余量。

P08 侧向制动证据包括 8 帧实际车辆模型的转向、制动和旧轨迹监护；该短段没有到达原侧向终点。提前制动停稳及恢复另有完整模型证据，采用上述独立的真实停车结果，不将其称为侧向目标到达。

这些是组件合成测量，**不能据此保证整链 20Hz**。复杂动态求解、地图及区域准备、独立检查应在实际硬件上测量；有限检查数不能代替实测算时。现场控制滞后超过原误差范围时会保护，不自动放宽范围。

普通跨地图接头的车辆模型正例明确给道路发布 API 50ms 工作预算；生产默认仍为 5ms，来源有效期限与运动误差没有改变。真实 Python 3.6 测试中曾出现 6.39ms 的道路发布工作，生产 5ms 模型因此正确保护。这段正例证明实际路径接续与整车检查，不能证明生产 5ms 预算下连续可用；仍需队长实测 SDK 调用及运行预算。预算不能中断阻塞的 SDK 调用。
