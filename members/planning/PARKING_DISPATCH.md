# P04 固定入口、原任务与实际反馈

本增量接在[正式泊车事实](../decision/PARKING_EXECUTION.md)及
[既有候选生成器](PARKING_CANDIDATES.md)上。继续使用 ParkingPolicy、
BehaviorSession、P02 整车校验、ControlEngine 和 BehaviorTransport；没有
另建阶段机、停车计时器或车辆指令通道。默认能力及 `send_control=false` 保持。

## 显式接入

固定 `plan(perception, decision)` 新增 PARK 消费者。集成方可通过
`configure_planning(..., parking_inputs_provider=...)` 提供
[ParkingPlanningInputs](parking_behavior.py)。默认没有提供者，PARK 会拒绝；
声明能力并不会生成任务、标定、覆盖或可行路径。

输入复用公共 ParkingMission，明确原任务 Evidence、地图、车位、道路集合、
入口和后轴接近/预入/驶出位姿。旧决策 import 仍指向同一类型。实际车型、
运动限制、当前实测曲率、有限预测、搜索、预算和来源期限必须独立提供。
显式 `(位置容差, 朝向容差, 停稳速度)` 须与实际决策和控制配置核对一致。
类名、模型 ID 或 task/verified_fusion 标签不构成物理标定或通行权证明。

原任务和所有阶段目标、地图/车位几何、车型/限制、容差、来源与模型身份
在同一意图中绑定。请求修订及创建帧/时间单调核对；新鲜 GPS 不刷新旧任务、
Sensor、覆盖或预测期限。公共帧和输出沿用现有序列化，没有新增 wire 字段。
公共 Evidence 与 ParkingMission 移到 core 供两方复用，旧 import 保持兼容；
P03/P04 的模型快照共用原校验逻辑，不复制另一套模型输入。

## 队长接线与运行监护

[CaptainRuntime](../../runtime.py) 可显式接收 `parking_inputs_provider`，回调返回
[ParkingIntegrationInputs](../../parking_integration.py) 或无任务时的 None。输入包含
原 ParkingDecisionInputs、ParkingPlanningInputs 和独立的监护工作预算，不会从
SDK 车位/题号、原始 steering 或缺省零值制造任务、车型标定和实测曲率。

队长在三个固定入口前每个原始帧只读取一次；两方收到分离快照。任务与原证据、
模型身份/时钟/期限、车身范围、到位容差及实际控制几何须一致。重复 GPS 不刷新
模型来源；提供者失败、未准备新帧、撤回、配置不符或过期均不能复用旧移动输入。

默认提供者为 None、能力不增加。显式完整 `parking_actions=PARKING_ACTIONS`
另要求成对提供者和可用控制配置；仅安装回调不会声明能力。配置与输入声明不是
物理标定或通行授权证明。没有增加配置文件开关、实际案例任务选择或 SDK 调用。

运行监护重新核对原任务/目标、当前能力、阶段/修订、实际方向与起点，再使用
[公开当前路径复核](parking_scene.py) 和原 P02 整车扫掠，重新读取道路/车位、
Sensor 对象、预测和完整视野。监护预算与规划搜索独立，未知、超限、来源变化或
超期撤销本次移动。已知名义碰撞产生紧急制动候选；其他未决产生受控制动候选。
只有通过此复核的泊车轨迹才用该路径检查替代前方路线 TTC；原 GPS/车道/必需目标、
信号、紧急制动与恢复保护保留。其他轨迹的倒车标志、普通前进时的实际倒退不放行。

移动轨迹的首点保持实际位置、朝向和速度。零速保持仅允许原显式停稳阈值内的
当前标量/向量速度，且整段静止、零停距、控制零油门并有刹车；不修改 GPS 或
把微小残速写成实际零速。监护也不会修改输入控制命令，或生成到位/停留反馈。
`latest_pipeline.json.parking_integration` 区分未配置、来源缺失和当前复核结果。

[队长接入回归](../../tests/test_parking_integration.py) 使用实际固定入口和
CaptainRuntime 循环，适配器为离线替身、发送关闭。连续滞后模型循环也逐帧经过
成对输入和真实 SafetySupervisor，继续检查原阶段、十秒义务、驶出及不重复启动。
这些都是明确合成来源/车型的功能验证；实际源耗时、控制响应、合法入口与现场
评分没有由此得到证明。完整验证结果见本文最后的运行接线验证记录。

运行接线验证记录：本轮新增 **17 项**队长接入/监护回归；相关专项 **40 项通过**。
最终代码在 SimOne **Python 3.6.4** 完整执行
`python -B -m unittest discover -s tests -v`：**1303 项全部通过，0 失败、
0 跳过，438.647 秒**。包含成对输入和真实监护逐帧参与的原完整泊车循环，
以及实际 CaptainRuntime 的离线观察模式循环。三个固定入口签名保持，10 个
本轮文件范围、Python 3.6 语法、60 个本地文档链接和差异检查通过。
下文的 1245/1265/1286 项是各历史增量的结果。本轮未初始化实际案例或发送控制。

## 阶段与执行

只支持 `APPROACH → POSITION → REVERSE_ENTRY/ALIGN → PARKED_DWELL →
EXIT_PREPARE → EXIT`。冷启动只能从 APPROACH 开始；切阶段须有上一段已
接受的路径、匹配意图/修订的新鲜控制或运行反馈，以及当前 GPS 的真实到位
和停稳。规划 PLANNED 不能推进阶段。倒车/保持段另查 REVERSE/DWELL 能力。

原 `parking:<id>` 在倒入及停车保持中延续；至少 10 秒由已有控制器的实际
停稳记录与反馈证明。EXIT_PREPARE 不创建新倒计时；随后仍经原换向互锁
停稳换挡。APPROACH/POSITION/EXIT 的无停留到位也须有控制诊断、当前 GPS
终点位置/朝向和停稳速度共同证明。传输层距离进度不等于到位或完成。

STOP、紧急制动和必需信号停车优先于移动泊车请求。到位保持也重新检查
当前完整车身、道路/车位、对象和可见范围，不能因位置很近跳过来源检查。

## 连续规划与收尾

每段保存已选择的不可变几何参考；下一帧从实际 GPS 接到剩余路径，按实际
速度/曲率重新计时。最多四个接回锚点，使用显式采样间距；完整剩余段重查
整车扫掠、预测、覆盖及目标整车容纳。缓存不保留动态安全结果、旧速度或
旧时间，超限撤销。接回失败才在原预算内重新搜索。

ParkingSearch 可显式提供 `terminal_straight_m`，默认 `(0.,)` 保留原单曲线。
非零值在转弯连接后接同方向、同终点朝向的直线；连接处零曲率，整段一起
重新计时及校验。全部切向、速度与直线组合最多 64 个，点数和统一工作预算
另有限制。车位倒入候选保留原目标朝向，不把整个朝向容差消耗在名义终点。

近终点无法回接精确参考点时，另检查按**当前实测曲率**走局部圆弧/直线后
停进原到位范围的候选。它不修改请求目标或容差；候选终点须同时满足原
位置/朝向范围及整车容纳，当前实际位姿仍由决策复核。仅允许局部路径，
不能绕整圈或反向；初速、制动距离、转向及完整路径仍通过 P02。

初速稍高于请求速度时，保留实际初速，在物理限制内按制动包络降到请求
上限；不把初速伪造为上限。这个选项仅供 P04，P03 旧默认保持。若停稳后
当前转向使所有候选不可证实，可发布经当前整车/视野/对象检查的零速保持，
复用控制器居中方向盘；不附 PLANNED、行为到位或停留义务。下一帧必须
重读实际曲率，原接受/进度超时继续生效。

## 验证范围与剩余项

[固定入口回归](../../tests/test_planning_parking_behavior.py) 使用正式目录/
环境读取、实际 ParkingPolicy、固定规划/控制入口、BehaviorTransport 和
有响应滞后的双向车辆模型，逐帧完成原阶段、实际停稳、至少 10 秒停留及驶出。
没有手写到位反馈或替换生成器。合成任务明确提供可执行接近/预入位姿；另
检查不可行短侧移、原模型/目标/修订绑定、当前对象/视野撤销、能力、预算、
期限、零速准备及到位范围收尾。[候选回归](../../tests/test_planning_parking_generator.py)
补查末端直线的速度时间、整车/可见/对象约束和有限组合/点数。
功能闭环采用统一虚拟时钟，来源期限和次数耗尽另有拒绝测试；这些结果
不能保证真实驾驶循环频率或硬实时。

后续[同帧覆盖接入](../../perception/MANEUVER_ENVIRONMENT.md#同一原始-sensor-包的完整覆盖)

不靠新增“已覆盖”标志绕过读取端；原期限、未知区域、对象及阶段到位规则
继续有效。视野跨片并不提供真实 Sensor 校准或自动任务选择。
